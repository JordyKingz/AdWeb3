## Application assets to prepare

- [ ] **Founder profile:** name, relevant experience, role, and verified public links.
- [ ] **Project link:** website, repository, or shareable brief, using an actual accessible URL.
- [ ] **Current game recording:** suggested 60–90 seconds showing ordinary gameplay, a level result, and offline continuation. Label its actual platform (currently evidenced Candy Blocks source is iOS) and existing gameplay; do not present it as an Android or AdWeb3 demo.
- [ ] **Three to five real screenshots:** onboarding/gameplay/result screens. Label any proposed sponsor design as a mockup; never present it as implemented.
- [ ] **Architecture overview:** use the feature-spec diagram or a concise reviewed export. Mark it proposed.
- [ ] **Budget and milestone proposal:** applicant-approved figures and scope, with any external review quote if used.
- [ ] **Discovery evidence:** dated notes from actual advertiser/player conversations; obtain permission before naming organizations or sharing quotes/contact details.
- [ ] **Traction evidence, if any:** analytics export or verifiable records with metric definitions and dates. Until available, state no verified platform metrics.
- [ ] **Optional deck:** only if the form/reviewer requests it or the applicant chooses to add one. A deck is not verified as mandatory.

## Future grant-delivery evidence

Do not fabricate these to make the application appear further along:

- Verified testnet contract addresses and deployment revisions.
- Funding, refund, settlement, and payout transaction links.
- Automated test results tied to an identifiable source revision.
- Nemesis and Pashov internal audit reports with tool/source SHAs, scope/completion status, verified findings, Foundry regression/fix results and both-tool retest evidence; do not present these as an independent production audit.
- Physical Android-device end-to-end prototype recording distinguishing test assets from real money, with app/package identity, SDK version, and integrity-validation results.
- Android game-slice source/build evidence; if rules are translated, seeded fixture results against the reference rules, plus lifecycle, offline-save, expiry, and wallet-return verification.
- Ledger reconciliation and actual measured payout-cost report.
- Actual interview/playtest findings and remaining risks.
